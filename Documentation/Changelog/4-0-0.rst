=================
4.0.0 - TYPO3 v14
=================

Breaking changes
================

*   Requires TYPO3 v14 and PHP 8.2 or higher.
*   New table names `tx_cal_domain_model_*`, categories are `sys_category`
    records, the plugin is the content element `cal_controller`. Upgrade
    wizards migrate the data of cal 1.x, see :ref:`upgrade`.
*   Extbase controller with Fluid templates instead of the marker based
    templates. TypoScript settings moved to `plugin.tx_cal.settings`.
*   Removed: frontend editing and the rights management, search, RSS,
    subscription and meeting manager, todo views, e-mail notifications,
    mini calendar, AJAX views, `wec_map` and captcha connections.
*   The extension `caldav` is part of cal now and must be uninstalled.
*   The location and organizer views use the CSS class `record-view` (formerly
    `place-card` / `profile-card`), the description of organizers the class
    `description` (formerly `bio`).
*   Removed plugin fields and TypoScript settings without function (taken
    over from cal 1.x): calendar name, subscription (`allowSubscribe`,
    `subscribeFeUser`, `subscribeWithCaptcha`), week start day, distance of
    nearby calendars (`view.calendar.nearbyDistance`), the pages of the year,
    month, week, day and list view (`view.<view>.<view>ViewPid`), mini calendar
    and list in the month view (`monthMakeMiniCal`, `showListInMonthView`),
    `view.list.maxRecurringEvents`, the page browser (`view.list.pageBrowser`),
    `view.event.isPreview` and the tab "Other View" (`view.other.*`). The tabs
    "Year View", "Month View" and "Week View" are removed, the tab "Day View"
    is now "Day and Week View". Values stored in existing plugins are ignored.
*   Removed the unused field `tx_cal_calendar_subscription` of frontend users.
*   Removed the PHP constant `DATE_CALC_BEGIN_WEEKDAY`, use the setting
    `view.weekStartDay` instead.
*   Removed the tables of attendees, subscriptions (monitoring) and unknown
    users, the event types "Meeting" and "Todo" (upgrade wizard
    `cal_eventTypes`), the fields of shared users, frontend editing, the
    free / busy view and nearby calendars, unused templates, language labels
    and the stylesheet `events.css`. Remove the database fields with
    "Analyze Database Structure".
*   Removed the extension settings `useLocationStructure` and
    `useOrganizerStructure`: events use the locations and organizers of cal,
    `tt_address` and frontend users are no longer supported as location or
    organizer. Other record types can still be added with own listeners of
    `GetLocationEvent` / `GetOrganizerEvent`.
    Remove the column with "Analyze Database Structure".

Features
========

*   Site sets "Calendar Base (cal)" and "Calendar Base (cal): default styles".
*   New design of the month, week, day and year view: time grid with
    overlapping events side by side, configurable day range (default 07:00 to
    23:00), year view with a dot per day and the events on hover.
*   List view with event cards, event view with images and lightbox.
*   Location and organizer views, links from the event view if the views are
    allowed.
*   Speaking URLs with the route enhancer
    :file:`EXT:cal/Configuration/Routes/Cal.yaml` and URL segments of events,
    locations and organizers, see :ref:`speaking-urls`.
*   Category colors with priority.
*   First day of the week (Monday or Sunday): site setting / TypoScript
    `view.weekStartDay` and field of the plugin.
*   Events of the types "Shortcut to page" and "Link to external url" link to
    the page / URL in all views. Locations and organizers without record link
    to the page or URL of the event.
*   Storage folders: `plugin.tx_cal.settings.pidList` limits the events,
    locations and organizers to these folders, `recursive` includes their
    subpages.
*   CSS custom properties for an own design, see :ref:`styling`.
*   Import of external calendars and ICS files with automatically created
    scheduler tasks.
*   CalDAV server at :samp:`<site base>/caldav`, :samp:`<site base>/.well-known/caldav`
    redirects to it (service discovery).
*   PSR-14 events instead of the service registry of cal 1.x.

Bugfixes
========

*   Recurring events follow RFC 5545: yearly rules with `BYMONTH`,
    `BYMONTHDAY` (also negative values), `BYDAY` with ordinal and `INTERVAL`.
*   All-day events of several days are exported with the correct `DTEND`, so
    CalDAV clients show them on all days (upgrade wizard `cal_icsData`).
*   The iCalendar download is only available if the view "ICS" is allowed.
*   Events without start day (e.g. saved with an invalid date) no longer break the
    recurrence index, the current day is used instead.
*   Calendars, events, locations and organizers are found independent of the
    storage page of the plugin (the repositories did not apply the query
    settings of the base repository), use `pidList` to limit them.
